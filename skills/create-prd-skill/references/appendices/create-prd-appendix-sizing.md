# 需求分级与文档体量适配

> 在阶段 0 完成产品定型后加载此文件，判断需求级别并确定文档体量。

## 分级判断逻辑

按**变更影响面**判断，不按主观感受。依次检查：

```
是否新建系统/业务域/子系统？ → 是 → L4（系统级）
        ↓ 否
是否新增页面、新增实体、新增角色/权限？ → 是 → L3（模块级）
        ↓ 否
是否修改/新增业务规则（校验、审批条件、计算逻辑等）？ → 是 → L2（规则级）
        ↓ 否
仅配置/文案/样式/阈值变更 → L1（配置级）
```

判断完成后，用一句话向用户确认：

> 根据描述，这是一个 **L{X}（{级别名}）** 需求，我会生成 **{体量描述}** 的文档。如需调整深度请告诉我。

等待用户确认后再继续生成。

## 四个级别详细定义

### L1 — 配置级（1 页变更卡片）

**判断信号**：不涉及新页面、新实体、新流程、新角色。只改现有配置/规则/文案/样式/阈值。

**典型场景**：
- 下拉框增加一个选项
- 修改校验提示文案
- 调整阈值（如审批金额上限从 5 万改 10 万）
- 修复计算公式 bug
- 调整列表默认排序

**输出结构**：

```md

| 编号 | MRD-XXX |
| --- | --- |
| 提交人 | {姓名} |
| 日期 | {日期} |
```

## 边界场景设计原则 — 所有级别通用

边界场景是 B 端 PRD 中最容易被忽视但上线后最容易出问题的部分。**每个级别都必须覆盖**，只是深度不同。

### 各级别边界场景要求

| 级别 | 要求 |
|------|------|
| L1 | 必须回答：在途数据怎么办？并发修改怎么办？生效时间点前后的衔接？—— 即使只改一个阈值 |
| L2 | 按规则逐条列出边界 case：规则冲突、空值/极端值、时序问题、并发、关联数据一致性 |
| L3 | 完整覆盖 5 类异常（网络/并发/数据/误操作/业务超时），每类有处理策略 |
| L4 | L3 + 降级方案 + 灾备 + 审计日志 + 敏感数据保护 |

### 边界场景检查清单（生成时逐条过）

1. **并发**：两人同时操作同一对象会怎样？
2. **在途数据**：变更生效瞬间，正在流转中的数据怎么处理？
3. **时序**：A 操作和 B 操作有先后依赖，乱序了怎么办？
4. **空值/极值**：字段为空、为 0、为最大值时逻辑是否成立？
5. **回滚**：操作出错后能否撤回？撤回后关联数据是否一致？
6. **关联影响**：改了 A 表的数据，B 表引用了 A 表的数据，B 表怎么办？
